# InOther-side — תוכנית בנייה (מערכת ייצור)

> מקור האמת לאפיון: [`PLAN.md`](./PLAN.md). המסמך הזה מתאר **איך** בונים, בשלבים.
> כל שלב מסתיים בקוד שרץ, בבדיקות שעוברות וב-commit.

## החלטות שנקבעו (ADR מקוצר)

| # | החלטה | נימוק | חלופה שנדחתה |
|---|---|---|---|
| 1 | **Monorepo עם pnpm workspaces** | שיתוף סכמות Zod בין web ל-api | ריפו נפרדים |
| 2 | **Fastify 5 + TypeScript** ל-API (במקום NestJS) | קל ומהיר, פחות "קסם", שכבות ברורות (routes → service → db). חבילות הליבה מוכרות ויציבות | NestJS: DI כבד, דקורטורים, יותר boilerplate |
| 3 | **Drizzle ORM + PostgreSQL 16 + pgvector** | שאילתות פרמטריות עם טיפוסים, מיגרציות SQL שקופות | Prisma: מנוע בינארי, פחות שליטה ב-SQL |
| 4 | **Auth בתוך המערכת** על פריימיטיבים מוכרים: argon2id, session token אטום שנשמר כ-SHA-256, TOTP ‏(RFC 6238) דרך `@oslojs/otp` | מידע רגיש מאוד, ולכן לא מעבירים זהויות לספק חיצוני. זו הגישה שמומלצת היום אחרי ש-Lucia הוצאה משימוש | Clerk/Auth0: ספק נוסף שמעבד מידע אישי, ועלות. **מחייב בדיקת חדירות לפני השקה** |
| 5 | **הצפנת מעטפה (Envelope)**: מפתח נתונים (DEK) לכל כספת, עטוף במפתח-על (KEK) | crypto-shredding במחיקה. ממשק `KeyProvider` שמאפשר מעבר ל-AWS KMS | הצפנת דיסק בלבד |
| 6 | **Zod 4** לכל ולידציה, משותף לקליינט ולשרת | מקור אחד לחוקי קלט | — |
| 7 | **Vitest + PostgreSQL אמיתי** לבדיקות אינטגרציה | בדיקות הרשאה (IDOR) חייבות DB אמיתי | Mock ל-DB |
| 8 | **כספת אחת למשתמש, בנתיב `/vault`** (בלי מזהה ב-URL) | אי אפשר לפנות לכספת של אחר. זה מבטל סוג שלם של IDOR | `/vaults/:id` (כפי שהופיע ב-PLAN) |
| 9 | **טוקנים בקישורי מייל נשלחים ב-fragment** (`#token=`) | לא נשלחים לשרתים ולא דולפים דרך Referer או לוגים | query string |
